# Overhaul verification

Run the Gradle wrapper with `:app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest :app:lintDebug`. Run `bash scripts/security-check.sh`, `python scripts/verify-document-migrations.py`, and `git diff --check`. Use the source and output reports from the same checkout. Keep device and staging results separate from JVM checks.

| Acceptance requirement | Verification procedure |
| --- | --- |
| All screens share controls, sizing and icons | Review all routes in the [screen inventory](APP_WIDE_DESIGN_REMEDIATION.md), including overlay and error states. Run `rg -l 'import androidx.compose.material.icons' app/src/main/java` and expect the Material registry only. Test minimum targets with TalkBack. Verify phone portrait/landscape, 600 dp and 840 dp widths, light/dark, and 1.6× text. |
| Me and Settings | Run `MeOverviewPinsDeviceTest` for encrypted layout persistence, display preferences, and account separation. Pin a legal name, a sensitive profile field and a card. Confirm legal name appears immediately, approved profile values persist, and the card shows four digits while its full detail still requires Vault unlock. Reorder and unpin, restart, and verify the source records remain. |
| Vault grouping | Open IDs containing national, school, library, passport and custom records. Filter by type, open and edit existing records, and verify original identifiers and attachments in authenticated detail. Check cards and bank accounts are still reachable. |
| Vault pinning | Run `MeVaultPinPickerDeviceTest`. Open Me, choose Add then Vault items, and complete strong-biometric authentication. Pin a card and a login, then check both appear on Me. Open Vault and use Pin to Me to unpin one record. Verify it remains in Vault. Cancel the biometric prompt or let the session expire and confirm the picker closes. |
| Education and Portfolio | With no records, check optional groups are hidden. Open the full-width Add information sheet and add a qualification, certificate, project and portfolio link offline. Relaunch and verify the records. Exercise Attach ID and Add number in the profile form. |
| Medical Aid | Check Care team is hidden until a doctor or facility is saved. Add one from the global Medical menu. Compare trailing Add alignment at compact and wide widths. Verify records and source delete confirmations remain accessible. |
| Image restoration | Use synthetic JPEG, PNG and WebP fixtures at different dimensions. Hash the app-owned source and authorized restored bytes. Verify orientation and viewport scaling in thumbnails and full views. Verify old cloud images restore in their existing fidelity. |
| People and notes | In upgraded data, verify an original note and its duplicate appear once and a distinct structured note keeps its attachments. Open a tagged journal note from People and a tagged People note from another person’s profile. Verify ambiguous labels and URL fragments remain unlinked. Delete a private note, relaunch, and confirm unresolved historical copies still require Vault authentication. |
| PIN and protected routes | Cover unconfigured, configured, change/remove, invalid and valid PIN, persisted throttling, restart, and missing device authentication. Check normal Library, note, health and Vault entry points; test window privacy, biometric failure and Vault expiry. Use a test profile and credentials. |
| Library | Search by title, person name, note text, a Unicode hashtag, permitted document metadata, and education and portfolio descriptions. Open the linked person or source note by selecting its Library result. Confirm National ID and password results are categorized separately. Check that protected content stays masked and opens through its authenticated source. |
| Library layout | Browse All information to verify category groups, line spacing, and long-title wrapping. Review addresses, phone numbers, dates, and records with multiple labeled fields at default and enlarged text. Compare search and copied values with the originals. |
| Phone feedback | In dark and light themes, open Library and check the title, data rows, search and single category menu. Open Edit from Home, choose Add information and type `addr`. Confirm the muted completion and category, then test a link and a custom title. Save a note and inspect its shared success tick, lock and unlock controls. |
| Offline and conflicts | In an authorized test account, disconnect networking, commit adds/edits/removals, and kill and restart the app. Verify local visibility, pending counts, reconnection and durable retry. Edit the same note on two devices and verify both copies remain until an explicit resolution. Test failures and account changes. |
| Existing records and restore | Exercise all historical schema upgrades and open representative data and attachments. Compare existing stable IDs and metadata. Run a second-device authorized restoration and compare records and original media. |

Production deployment, device installation and account-specific cloud verification require a suitable destination. Use staging and synthetic data for these checks.
